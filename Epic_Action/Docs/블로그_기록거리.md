## 1. "무기가 주인공인 액션 게임" — 기획과 구조
- 아이디어: 사람이 무기를 드는 대신 무기가 스스로 걷고, 뛰고, 싸운다
- 핵심 구조: `Avatar > Pose > Motion > Visual` 3단 계층
  - Pose는 공격 포즈(기존 WeaponSwinger 재사용), Motion은 이동 연출이 맡는다. 서로 덮어쓰지 않는다
- 기존 시스템 재사용: 판정(WeaponHitbox), 절단, 히트 피드백을 그대로 쓰고 컨트롤러만 새로 만들었다
- 넣을 자료: 계층 다이어그램, 무기 4종이 움직이는 GIF

## 2. 무기별 이동 설계 — 형태에서 움직임을 끌어내기
| 무기 | 이동 아이디어 | 글 포인트 |
|---|---|---|
| 자 | 끝을 축으로 텀블링 | 넘어지기 90°는 아래 끝 기준, 일어서기 90°는 위 끝 기준으로 회전축을 바꾸는 수학. 몸통이 이동해도 바닥 접점은 고정되게 |
| 가위 | 두 날이 다리처럼 교차 | 기존 ShearsDriver가 닫힌 각도 아래로 못 가게 막혀 있어서, 걸을 때만 날을 직접 회전시켜 우회 |
| 전기톱 | 체인 날로 굴러가듯 구동, 튕기는 공격 | 바닥에 눕혀 미끄러지기 → 날을 세워 구동 → 공격도 바닥을 튕겨서. 플레이 피드백으로 바뀐 과정 |
| 총 | 반동 사격으로 이동, 아래로 쏴서 점프 | 무기의 기능(사격)을 이동 수단으로 바꾸는 발상 |
- 넣을 자료: 무기별 이동 GIF, 자 텀블링 회전축 그림

## 3. 플레이 피드백으로 진화한 전기톱 (반복 개선 기록)
1. 바닥에 눕혀 미끄러짐 → "날로 움직여야 자연스럽다"
2. 날을 세워 구동 + 4연타 → "너무 느리다", "1타가 정면을 못 벤다"
3. 속도 상향 + 회전 시작 방향 수정 + 튕기는 점프 → "갑자기 공중부양해서 어색하다"
4. 지상 공격은 모두 바닥을 차고 튕기기, 회전 베기는 공중 전용으로 분리
5. 1타를 땅을 박차는 360° 대각선 회전베기로: 선딜에 몸을 눌렀다가(웅크림) 풀면서 도약. "도약은 코드에 있는데 박차는 게 안 보인다"는 피드백 → 준비 동작이 없으면 점프로 안 보인다
6. 일반 클릭도 홀드처럼 갈아버리기: 즉시 절단 조건(홀드 여부)을 빼서 클릭과 홀드의 차이를 없앴다. 공격 방식(콤보)은 클릭 그대로 유지
- 글 포인트: "모든 공격은 지면 반동에서 시작한다"는 규칙 하나가 어색함을 정리했다. 그리고 "움직임은 있는데 안 보이는" 문제는 수치가 아니라 예비 동작(anticipation)이 원인일 수 있다
- 넣을 자료: 단계별 비교 GIF(같은 각도로 찍기)

## 4. 데이터 주도 + 빌더 스크립트로 씬 재현하기
- 원본 WeaponData를 복제해 아바타용으로 다시 포즈를 잡았다. 원본 씬에는 영향이 없다
- 메뉴 한 번으로 씬과 데이터를 다시 만든다. 재현은 쉽지만 함정이 있다: "빌더를 안 돌려서 총이 안 나온 사건"
- 모델 바운즈로 총구 위치와 바닥 높이를 자동 계산하는 방법

## 5. AI 멀티 에이전트로 게임 기능 만들기 (AX 실험기)
- 역할 분담: 메인 Claude(설계·통합) + 서브에이전트(Sonnet·Haiku) + Orca로 띄운 Codex 워커(gpt-6.1-sol)
- 잘 된 점: 파일 소유권 단위 병렬화, 설계 단계에서 추천값을 붙인 질문
- 실패와 교훈
  - Haiku가 "사용자 확인이 필요하다"는 개인 지침 때문에 위임받은 작업을 거부함
  - 워커 터미널 PATH 문제, 작업 지시가 붙여 넣기만 되고 전송되지 않은 문제
  - AI는 플레이를 못 한다. 손맛은 사람이 판단한다
- 넣을 자료: 워크플로 다이어그램(`Docs/AI활용_개선점.md` 4번), 요청 1건당 왕복 횟수 비교

## 6. 총 개조기 — 개머리판으로 통통, 쏴서 점프, 가늠좌로 조준
- 이동: 개머리판을 땅에 대고 세운 채 0.3초마다 작은 홉(착지 때 길이 방향으로 찌그러짐). 사격 반동으로 밀던 이전 방식을 걷어냈다
- 점프: 총구를 아래로 뒤집고 4발을 쏘며 한 발마다 속도를 올려 2.4m까지. "총을 쏴서 점프"를 4발 연사의 누적 추진으로 표현
- 입력 재배치: V = 근접, 우클릭 = 조준, 좌클릭 = 연사. 다른 무기의 우클릭은 그대로 두려고 입력 구조체에 `melee` 필드만 추가
- **가늠좌 조준 시점 만들기** (핵심 소재)
  - 모델에 후방 조준환과 전방 가늠쇠가 있지만, OBJ 정점을 직접 읽어 보니 두 점을 잇는 선이 총 축에서 약 5.85° 위로 기울어 있었다
  - 모델을 그대로 믿지 않고 조준환→가늠쇠 직선이 화면 중앙에 오도록 총의 pitch를 `카메라 pitch + 기울기`로 보정하고, 카메라는 조준환 뒤 0.1m에 둔다 (near clip을 0.02로 낮춰 링이 잘리지 않게)
  - 시점은 마우스, 총이 그 방향을 따라 겨눈다. 조준 중에는 크로스헤어를 숨기고 보조 조준을 끈다
  - 함정: OBJ가 유니티에서 렌더러 1개로 합쳐져 이름으로 파트를 못 찾는 문제 → 임포트 결과를 먼저 확인했어야 했다 (실패담으로 쓰기 좋음)
- 넣을 자료: 조준환 링 너머로 보이는 가늠쇠 스크린샷, 보정 전/후 조준선 비교, 정점 좌표 표

## 7. 짧은 팁 글 후보
- PowerShell 5.1에서 따옴표가 든 긴 문자열을 네이티브 CLI 인자로 넘기면 깨진다 → Bash나 파일로 전달
- 오일러 각 보간(LerpUnclamped)으로 "몸 회전(bodyYaw) + 무기 포즈"를 겹쳐 회전 베기 만들기
- 에디터 메뉴 자동 실행(MCP `invoke_menu`)은 저장 확인 창에서 멈추거나 예외가 나도 success를 돌려준다 → 결과 파일의 수정 시각으로 검증
- 피벗 기준 포즈: 회전할 점(조준환·개머리판 끝)을 월드의 한 점에 고정하려면 `Motion 위치 = 목표점 - 회전 × (스케일 × 피벗)`
